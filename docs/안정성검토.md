## 2026-10-13 v5.3.5 최초 관리자키 오류 안내

실제 보존된 v4 서버 코드로 v5 info 요청 시 관리자키 검증이 먼저 실패하는 것을 재현했습니다. 이 최초 확인 요청에만 업데이트 안내를 표시하며, 정상 로그인·최초 계정 생성·연동 테스트·서명 요청의 키 오류를 덮어쓰거나 키 검증을 우회하지 않습니다. 해당 학교의 실제 배포 버전은 주소를 확인한 뒤 별도로 확인해야 합니다.

## 2026-10-12 v5.3.4 첫 접속과 v4 안내

학교 주소가 없는 공용 사이트에서는 안내를 자동 표시하고 주소 입력을 마지막 단계에 둡니다. v4를 선택하면 기존 프로젝트의 코드 교체·설치 준비·기존 주소 재배포·최초 계정 설정·기존 자료 연결 순서로 안내합니다. v4 서버가 확인된 연결 오류 화면도 v4 안내를 자동 표시합니다. 이 안내는 설치·이전 함수를 실행하지 않습니다. 기존 학교 주소가 저장되어 있으면 로그인으로 바로 진행하며, 학교 주소가 없는 참여자 링크에 설치 절차나 계정 만들기를 표시하지 않습니다.

## 2026-10-12 v5.3.3 연동 확인

Google Drive 연동 탭에 전체 초기 안내와 관리자 연결키 입력란을 바로 표시합니다. 연동 테스트는 로그인 세션·CSRF·연결키를 확인한 뒤 현재 연결된 DB와 서명 시트를 읽습니다. 파일 이름·링크·연수 및 중복을 제거한 서명 개수를 반환하고 명단, 참여 토큰, 서명 이미지는 반환하지 않습니다. 확인 과정에서 자료 파일·파일 ID·관리자 계정을 수정하거나 재설치하지 않습니다. 오류가 나도 파일 이름 변경이나 시트 열 복구를 실행하지 않습니다. 키는 요청 직전에 입력란을 비우며 브라우저 저장소에 저장하지 않습니다.

검증: 단위 테스트 65개, GAS 단독과 공용 사이트 브라우저 시나리오 모두 통과. 가상 학교에서 잘못된 키, 정상 키, 잘못된 파일과 시트 헤더, 미인증 및 CSRF 오류와 자료 보존을 확인했습니다. 실제 학교의 관리자 로그인 후 연동 테스트는 담당자가 실행하여 현행 파일 읽기 상태를 확인합니다.

# v4.0.0과 v5.3.0 연동·저장 안정성 검토

## 2026년 10월 12일 연동 안내 복원

v5.3.2는 로그인 화면과 관리자 Google Drive 설정에서 **연동 방법 다시 보기**를 항상 열 수 있게 복원했습니다. 안내를 여닫아도 입력한 로그인 정보·학교 주소를 유지하고, 기존 계정 생성이나 자료 이전을 실행하지 않습니다. 새 설치·기존 업데이트 안내를 선택해서 볼 수 있습니다.

최신 코드 보기는 공개 GitHub의 고정된 코드·버전 주소만 로그인 정보 없이 조회합니다. 버전 불일치·잘못된 응답·과도한 크기는 복사 대상으로 표시하지 않고, 창을 닫으면 읽기 요청을 취소합니다. 관리자키의 실제 값은 조회하거나 표시하지 않으며 Apps Script의 확인 위치만 안내합니다. 기존 Drive 연결 표시가 각 자료 파일의 접근 가능 여부까지 진단하는 기능은 여전히 별도 구현 대상입니다.

자동 검사 **64개**, 타입 검사, GAS iframe 화면 검사 **17개**, 공용 사이트 화면 검사 **20개**를 통과했습니다. 가상 학교에서 안내 재열기·코드 복사·자격 증명 유지·계정 초기화 방지와 기존 설치·로그인·연수·서명·자료 이전을 검증했습니다.

## 2026년 10월 11일 문법 오류 수정

v5.3.0의 `Code.gs` 256행에서 Node 테스트가 허용한 논리 할당 문법(`||=`)이 실제 Apps Script 편집기의 저장 단계에서는 `ParseError: Unexpected token =`로 거부되었습니다. 아래 v5.3.0의 자동·화면 테스트만으로 실제 Google 편집기의 문법 호환성을 확인하지 못했습니다.

GAS v5.3.1은 해당 부분을 일반 `if` 초기화로 바꾸고, 설치 ZIP 생성 전에 `||=`, `&&=`, `??=` 연산자를 AST로 검사해 차단합니다. 서버 원본·배포용 사본의 일치와 오류 문법 거부를 회귀 검사합니다. 이 검사는 같은 종류의 오류 재발을 방지하기 위한 것으로 실제 GAS 런타임의 모든 문법·API 호환성 검증은 아닙니다. 화면은 v5.3.0을 그대로 사용하며, 변경 내용은 데이터 연결이나 저장 파일 형식에 영향을 주지 않습니다.

수정 후 자동 테스트 **61개**, 타입 검사, GAS·사이트 설치 패키지 빌드와 매뉴얼의 사진·링크 검사를 통과했습니다. 아래 15개·18개 브라우저 검사는 화면을 변경하지 않은 v5.3.0 때의 결과이며, 이번에는 실제 학교 프로젝트의 편집기 저장·배포를 직접 실행하지 않았습니다.

검토일: 2026-10-10. [보관된 v4 서버](../gas/legacy/TeacherSignV4.gs), [현재 서버](../Code.gs), 가상 Drive·브라우저 테스트를 비교했습니다. 실제 학교의 Google 서버 부하·응답시간은 측정하지 않았습니다.

**연결 유지·학교별 분리·관리자 인증은 개선됐고, v5.3.0에서 서명 교체 실패 시 이전 서명을 지우던 문제를 보완했습니다. 대용량·동시 접속 성능까지 전반적으로 더 좋아졌다고 단정하지는 않습니다.** 학교에 설치된 버전은 업데이트 화면에서 따로 확인해야 합니다.

## 개선된 부분

| 항목 | v4.0.0 | v5.3.0 |
| --- | --- | --- |
| 자료 파일 선택 | 같은 이름의 첫 검색 결과 | 최초에 파일 내용·개수를 확인해 선택하고, 이후 지정된 ID 유지 |
| 기존 자료 연결 | 이름 검색으로 읽음 | 관리자 화면에서 찾기 → 선택·확인 → 사용하기. 백업·사본 검증 후 연결 |
| 같은 계정의 여러 설치 | 동명이 DB·서명 시트 혼동 가능 | 프로젝트별 저장소·관리자 계정 분리 |
| 관리자 접근 | 연결키 | 관리자 계정·세션·CSRF·로그아웃·만료 확인 |
| 서명 교체 중 쓰기 실패 | 기존 기록을 먼저 삭제 | 기존 JSON·시트 기록을 유지한 채 새 시트 행 추가 |
| 완료한 쓰기 재전송 | 결과 기록 없음 | 같은 요청 ID·내용의 완료 결과를 제한 시간 동안 재사용 |

자료 이전은 v4 → v5 최초 한 번입니다. **이미 v5에 자료가 있으면 덮어쓰지 않고 중단**합니다. 같은 v5 프로젝트의 Code.gs·Index.html을 교체하고 기존 배포를 갱신할 때는 자료를 다시 이전하지 않습니다. 사용자가 지정된 파일을 지우거나 연결 값을 직접 바꾸면 연결은 깨질 수 있습니다.

## 서명 교체 실패 보호

v5.2.1까지는 JSON의 이전 서명과 시트의 이전 행을 삭제한 다음 새 서명을 썼습니다. 새 행 저장 단계에 오류를 주입하면 v4·v5.2.1 모두 기존 서명이 없어지는 상황을 재현했습니다.

v5.3.0은 **새 서명을 추가할 때 이전 JSON과 시트 행을 지우지 않습니다.** 같은 사람의 기록 중 최근 서명 하나만 화면에 표시합니다. 저장 순서는 서버에서 정하며, 참여자의 기기 시간이 오래된 경우도 교체가 반영됩니다. 관리자가 명시적으로 서명을 삭제할 때는 보관된 이전 기록도 제거합니다.

[서명 보존 회귀 검사](../tests/signature-preservation.test.mjs)에서 관리자·참여자 각각, 기존 기록이 JSON·시트 각각에 있는 네 조건에 저장 실패를 주입했습니다. 모두 이전 기록과 파일 내용이 남았습니다. 정상 교체·반복 교체 후 표시 서명이 하나인 것과 명시적 삭제도 확인했습니다.

이는 모든 저장 작업의 무손실 보장은 아닙니다. 여러 연수에 쓰는 도중의 부분 성공, 실제 Google 서비스 오류, 연수 삭제·편집 중 여러 파일 변경과 복원은 별도 검토 대상입니다. 교체 이력이 시트에 남기 때문에 기록 증가에 따른 조회 비용도 고려해야 합니다.

## 자료 연결의 검증 범위

[화면 연결 서버 검사](../tests/migration-ui.test.mjs)와 [편집기 이전 검사](../tests/migration.test.mjs)로 다음을 확인했습니다.

- 학교 관리자 로그인·CSRF 검증, 확인 화면의 세션 연결과 10분 만료.
- 후보 검색이 연결을 바꾸지 않고 명단·PIN·참여 토큰·서명 이미지를 브라우저에 보내지 않음.
- JSON·시트에서 겹치는 같은 사람의 서명은 한 번만 계산.
- 현재 v5 자료, 잘못된 시트, 변경된 원본·저장소, 복사·백업 오류 시 중단.
- 원본·기존 연결 파일·관리자 계정을 보존하고 복사본을 연결.
- 완료 결과 기록 중 오류가 나더라도 같은 확인 요청을 다시 보내면 복사를 반복하지 않고 완료 결과 확인.
- 브라우저 요청 제한보다 큰 JSON도 Drive 안에서 복사. 검색 후보는 파일 종류별 30개까지이고 제한 여부를 표시.

다른 GAS 프로젝트의 기존 앱과는 잠금을 공유하지 않습니다. 복사 중 원본 변경을 다시 검사하지만 **담당자는 연결이 끝날 때까지 기존 앱의 연수·서명 저장을 멈춰야 합니다.** 이름이나 수정일만으로 학교를 확정하지 않고 담당자가 제목·폴더·개수를 확인합니다.

## 아직 확인할 성능·백업

두 버전 모두 JSON 전체를 읽고 서명 시트 전체의 10개 열을 조회합니다. 가상 시트의 다른 연수 서명 1,000행을 두고 빈 연수 하나를 조회했을 때 10,010개 셀을 읽었습니다. 이는 읽기 범위 검사이며 실제 지연 시간 측정이 아닙니다. v5는 인증·조회도 프로젝트 잠금과 인증 파일 저장을 사용하므로 큰 학교에서 동시 접속 대기가 늘어날 가능성을 실제 조건으로 확인해야 합니다.

참여자 요청은 학교 전체에서 1분 창당 300회, 성공한 쓰기 결과 기록은 5분간 최대 200개입니다. 이 한도는 지원 인원·처리 속도 보장이 아닙니다. [Google의 실행 시간·동시 실행·서비스 할당량](https://developers.google.com/apps-script/guides/services/quotas)도 적용됩니다.

수동 백업은 [교사용 매뉴얼 14번](교사용매뉴얼.md)의 네 단계로 현재 연결된 DB와 서명 시트를 같은 날짜의 사본으로 보관합니다. PDF 등록부만으로 프로그램을 복원할 수는 없습니다. 전체 백업·복원을 수행하는 앱 버튼은 아직 없으며, 최초 이전의 자동 백업에는 이후 새 자료가 들어 있지 않습니다.
