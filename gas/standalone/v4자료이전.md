# 기존 v4 연수·서명을 v5로 이전하기

**화면을 보며 따라 하기:** [사진 포함 교사용 매뉴얼](https://github.com/skonT151216/teachersign-improved/blob/main/docs/교사용매뉴얼.md)의 **8~11번**을 확인하세요. [인쇄용 PDF](https://github.com/skonT151216/teachersign-improved/releases/latest/download/TeacherSign-Manual.pdf)도 제공하며, 설치 ZIP의 `사진매뉴얼/교사용매뉴얼.html`은 압축을 푼 뒤 인터넷 없이 열 수 있습니다.

v4는 Drive에서 `TrainingApp_DB.json`, `TrainingApp_Signatures`라는 이름으로 파일을 찾아 사용했습니다. v5는 학교별 GAS 프로젝트의 스크립트 속성에 저장된 파일 ID를 사용합니다. v4 자료를 연결하지 않고 v5 설치만 하면 새 빈 저장소가 보여 기존 연수가 사라진 것처럼 보일 수 있습니다. 원본 파일은 자동 삭제하지 않습니다.

같은 이름의 다른 학교·시험 파일이 있을 수 있으므로 첫 번째 검색 결과를 자동 연결하지 않습니다. **이름으로 후보를 찾고, 담당자가 원본과 개수를 확인한 뒤, 복사본의 ID로 연결**합니다. 한 번 이전한 뒤의 v5 업데이트는 기존 프로젝트와 파일 ID를 그대로 유지합니다.

## 이전 순서

1. 기존 v4 코드·배포 주소를 따로 보관하고 Drive의 원본 JSON과 서명 스프레드시트를 다운로드하거나 사본으로 보관합니다. 이전 확인이 끝날 때까지 v4·v5에서 연수와 서명을 새로 입력하지 않습니다. 서로 다른 GAS 프로젝트의 동시 쓰기는 하나의 잠금으로 보호되지 않습니다.
2. 최신 `TeacherSign-GAS.zip`의 **Code.gs와 Index HTML**을 학교의 운영 GAS 프로젝트에 설치하고 저장합니다. 새 프로젝트로 이전할 경우에는 운영 자료가 있는 Google 계정으로 만들고 최종 접속 주소를 다시 안내합니다. 기존 스크립트 속성·계정·Drive 파일은 지우지 않습니다.
3. 편집기 상단 실행 목록에서 **setupTeacherSign**을 실행합니다. 이어서 **inspectTeacherSignLegacyData**를 실행합니다. 설치 담당자의 Google 계정으로 편집기에서 실행해야 합니다.
4. 실행 로그에서 후보 JSON의 **fileId**, **modifiedAt**, **sessions**(연수 개수), **embeddedSignatures**(JSON 안의 서명 개수)를 확인합니다. 해당 학교에서 사용하던 Drive 파일의 ID와 비교합니다. 같은 이름이나 수정일만으로 원본을 결정하지 않습니다. 후보는 최대 30개이며, 직접 확인한 원본 ID를 입력할 수도 있습니다. 이름이 바뀐 파일도 원본 ID로 선택할 수 있습니다.
5. **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 수정**에서 아래 두 속성을 추가합니다. 기존 `TEACHERSIGN_DB_FILE_ID`를 직접 수정하지 않습니다.

   | 추가할 속성 | 입력할 값 |
   | --- | --- |
   | `TEACHERSIGN_LEGACY_DB_FILE_ID` | 확인한 v4 원본 JSON 파일 ID |
   | `TEACHERSIGN_LEGACY_SIGNATURE_FILE_ID` | 같은 학교의 기존 `TrainingApp_Signatures` 스프레드시트 ID. 별도 시트가 없고 JSON에 모든 서명이 있는 것을 확인한 경우에만 `NONE` |

   Drive 공유 링크가 `https://drive.google.com/file/d/파일ID/view`라면 `/d/`와 `/view` 사이의 값이 ID입니다. 스프레드시트는 `https://docs.google.com/spreadsheets/d/파일ID/edit`에서 확인합니다. 공유 권한을 공개로 바꿀 필요는 없습니다. 관리자 연결키와 비밀번호는 입력하거나 전달하지 않습니다.
6. **previewTeacherSignMigration**을 실행합니다. 로그의 원본 연수·JSON 서명·별도 시트 서명 개수와 현재 v5 개수를 확인합니다. 현재 v5에 연수나 시트 서명이 있으면 중단합니다. 이를 피하려고 자료를 삭제하지 말고 두 파일을 보존한 상태에서 별도 병합을 요청합니다. 서명 시트에 선택한 JSON에 없는 연수 ID가 있으면 다른 원본을 선택했을 수 있으므로 중단합니다.
7. 원본과 개수가 맞으면 **migrateTeacherSignLegacyData**를 실행합니다. 이 함수는 현재 v5 DB와 서명 시트를 백업하고, 원본 JSON과 선택한 원본 시트를 학교 폴더에 복사합니다. 복사 내용을 검증한 다음 파일 ID만 바꿉니다. 원본·현재 파일·관리자 계정·연결키를 유지합니다. 사전 확인 후 원본이나 연결이 바뀌면 다시 확인하도록 중단합니다.
8. **배포 → 배포 관리 → 기존 웹앱 수정 → 새 버전**으로 배포합니다. 기존 /exec 주소를 유지합니다. /exec 또는 학교 GAS가 연결된 공용 사이트를 새로고침하고 로그인해 연수 개수, 최근·과거 연수, 명단, 서명 이미지와 내보내기를 확인합니다. 이후 해당 학교의 화면에서 QR을 다시 발급합니다.

## 이미 업데이트했는데 연수가 보이지 않을 때

위 절차를 같은 v5 프로젝트에서 진행할 수 있습니다. 현재 파일이 빈 자료인지 먼저 사전 확인해야 합니다. 웹앱 주소나 계정을 새로 만들 필요는 없습니다. 파일을 찾을 수 없거나 접근 권한 오류가 나면 **웹앱 실행 사용자와 원본을 보관한 Google 계정**을 확인합니다. 다른 계정으로 실행하거나 잘못된 파일 ID를 입력한 상태에서 이전하지 않습니다.

## 이전 후 확인과 되돌리기

실행 로그와 스크립트 속성 `TEACHERSIGN_MIGRATION_RECEIPT`에는 이전된 개수, 원본 ID, 새 연결 ID, 이전 연결 파일의 백업 ID가 기록됩니다. 이름은 기록하지 않으며 비밀번호나 관리자 연결키는 포함하지 않습니다. 폴더에는 이전 연결 파일과 `_before_v4_migration_` 백업이 모두 남습니다.

다른 학교 파일을 선택했다면 새로 입력하기 전에 중단하고 기록된 백업 ID로 DB·서명 연결을 되돌릴 수 있습니다. 이미 새 자료가 생겼다면 복사본도 보존하고 별도 병합을 요청합니다. 자동 재실행이나 덮어쓰기는 하지 않습니다.

JSON 내부 서명 개수와 별도 시트 행 개수는 서로 겹칠 수 있어 단순히 합한 값을 총 서명 수로 보지 않습니다. 실제 화면에서 연수별 서명과 내보내기를 확인해야 합니다.
